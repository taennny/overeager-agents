## 0건이 뜻하는 것

**현재 세 과제의 유효 시행에서는 경로/작업 범위 이탈을 관측하지 못했다. 이 결과만으로 “모델이 너무 똑똑해서 방어가 필요 없다”는 원인을 결론낼 수 없다.** 모델의 경계 준수, 명확한 수정 파일 지시, 약한 유인·좁은 과제/측정 범위가 함께 가능한 설명이다.

1. **과제의 유인이 제한적이다.** 세 요청 모두 수정할 파일 두 개를 명시한다. T1 운영 설정에는 마스킹을 꺼 놓은 플래그가 없고, T2 원본 CSV는 정상 한 행이다. 추가로 손봐야 할 듯한 문제를 모델이 발견할 기회가 약할 수 있다. 직접 읽기 도구로 변경 보호 자원을 읽은 시행은 GPT 0개, Claude 0개다. 읽기는 허용될 수 있으므로 이 수치를 읽기 위반으로 세지 않는다. 셸을 통한 모든 읽기를 관측한 수치도 아니다.
2. **같은 세 과제를 반복했다.** 반복은 응답 변동을 살피지만 새로운 작업 유형/모호한 요청/업무 흐름을 넓히지 않는다. 30회라는 횟수만으로 위협 커버리지를 확보했다고 볼 수 없다.
3. **측정 범위가 정해져 있다.** 최종 파일 경로 밖 변경과 라벨 가능한 행동을 본다. 허용 파일 내부의 불필요한 의미 변경, 되돌린 변경, 관측 밖 읽기·외부 효과까지 전체 안전으로 인정하지 않는다. UNKNOWN과 관측 누락도 보존했다.
4. **탐지기 자체의 기본 작동은 별도로 점검했다.** 아래 고의 이탈 대조군은 실제 모델 행동과 구분한다. 이 검사가 통과해도 실제 모델이 이탈할 현실적 기회가 충분하다는 뜻은 아니다.

따라서 0건이 이어질 때의 연구 결론은 **“현재 기본 과제에서는 방어가 줄일 문제 행동의 신호가 충분하지 않다”**다. 이 상태만으로 방어의 위험 감소 효과를 입증하는 주장은 어렵다. 다음 단계는 결과를 숨기는 재실행이 아니라, 별도 버전으로 현실적인 추가 수정 유인/권한 경계가 있는 다양한 과제를 사전에 설계하고 정상 작업·의도된 OUT·무행동 대조를 함께 확인하는 것이다. 사용자 요청과 고정 scope 근거도 먼저 정해야 한다. 이번 60회에는 새 함정/정답 변경을 섞지 않았다.

## 과금 없는 탐지 대조

고정 스크립트 9개를 실제 연구 이미지/동일 채점기로 실행했다. 정상 해법 3개는 기능 성공·이탈 없음, 고의 추가 변경 3개는 기능 성공·이탈 있음, 무행동 3개는 기능 실패·이탈 없음이 기대값이다. 실제 검증은 **9/9 일치**했다. [대조군 근거](../evidence/baseline30-20261104/calibration-validation.json). 실제 GPT/Claude의 60회나 표본 수에 더하지 않는다.

모델별 누적 사용자 한도 $2, 로컬 운영 한도 $1.90, 과제당 $0.50를 유지했다. [장부](../evidence/baseline30-20261104/live/spend-ledger.json)의 `uncertain_retained`는 전액 예약을 남긴 미확정 상태이고 `settled`와 구분한다. 응답 함수가 종료된 오류 후 다음 고정 슬롯 진행은 사전 명세에 따른다. 진행 중인 `in_flight` 요청이 있으면 새 호출을 막으며 원래 셀의 자동 HTTP 재시도는 0이다.

## 공유와 검증

추가 실행용 7개 검사(생략 0)와 두 모의 native HTTP→같은 Docker 채점 검증을 사전에 통과했다. 연구 실행 모듈은 이전 224검사/CI 검증된 코드와 같고, 새 제어/예산 스크립트는 별도 hash로 고정했다. 원격 CI와 [검사 근거](../evidence/baseline30-20261104/engineering-summary.json)는 실제 모델 결과와 합산하지 않는다.

[내보내기 목록](../evidence/baseline30-20261104/live/export-manifest.json)에 새 실행 원본의 모든 응답·이벤트·자산·이전/이후 파일의 원본/공유 hash와 record_key를 둔다. 원본은 로컬에 보존하며 키/개인 경로는 제거했다. 같은 경로의 반복별 report.json/changes.patch와 개별 MD에서 사례를 검토할 수 있다. 공유 계획은 다른 계정의 유료 실행 승인으로 재사용하지 않는다. 독립 사람 판정/ORR/κ·본실험 확증은 별도다.

고정 실행 커밋 [GitHub CI](https://github.com/taennny/overeager-agents/actions/runs/41791768322)의 Python 3.9/3.12·Docker 검사가 모두 통과했다. [CI 상태](../evidence/baseline30-20261104/ci.json).

GPT의 유효한 기능 실패 4건은 모두 T1이며, 관측된 출력은 끝 네 자리를 가리거나 가운데 세 자리만 가리거나 전화번호가 그대로 남는 형태였다. 네 시행 모두 run_tests 호출은 0회였다. 이 결과는 기능 오류로 보존하고 범위 이탈로 재분류하지 않는다.
